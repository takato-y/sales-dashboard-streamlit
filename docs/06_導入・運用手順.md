## 1. 前提

| 項目 | 内容 |
|---|---|
| Python | 3.12（動作を確認したのは 3.12.3） |
| OS | Linux（WSL2）で確認。Windows・macOS では未確認 |
| ネットワーク | 導入時にライブラリを取得するときだけ必要。使うときは不要 |
| 利用範囲 | 認証がないため、利用者自身の PC で使う。社内ネットワークに公開しない |

## 2. 導入

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows の場合は .venv\Scripts\activate
pip install -r requirements.txt
```

テストと画面の撮影も行う場合は `requirements-dev.txt` を使い、Playwright のブラウザを入れます。

```bash
pip install -r requirements-dev.txt
playwright install chromium
```

## 3. 起動と終了

```bash
streamlit run app/streamlit_app.py --server.address 127.0.0.1
```

- ブラウザで `http://127.0.0.1:8501` を開きます（ポートは起動時の表示に従います）。
- 終了は起動した端末で Ctrl＋C を押します。読み込んだデータはメモリ上だけにあり、終了すると消えます。
- `.streamlit/config.toml` でも待ち受けアドレスを `127.0.0.1` にしています。`--server.address 0.0.0.0` のように変えると社内の他の PC から開けるようになりますが、認証がないため行わないでください。

## 4. 毎月の使い方

1. 販売管理システムから売上明細を CSV（または Excel）で出力します。列は `docs/04_入力データ仕様.md` のとおりです。
2. 画面のサイドバーで「ファイルを読み込む」を選び、複数月のファイルをまとめて選びます。
3. 画面上部に黄色の帯が表示された場合は「取込結果」タブで除外した行と理由を確認し、元のファイルを直して読み込み直します。除外した行は CSV で保存できます。
4. 期間・担当者・商品カテゴリ・地域を選び、各タブで集計結果を確認します。
5. 「出力」タブで Excel または印刷用ページを保存します。印刷用ページはブラウザで開き、印刷画面の送信先（プリンター）で「PDF に保存」を選びます。

## 5. 架空データ・サンプル

```bash
python scripts/generate_data.py                 # data/generated/ に月別 CSV を 24 本（2024-01〜2025-12）
python scripts/generate_data.py --format xlsx   # 月別 Excel
python scripts/generate_data.py --samples       # samples/ を作り直す
```

`data/generated/` はリポジトリに含めません（`.gitignore`）。

## 6. テストと画面の撮影

```bash
python -m pytest -v            # 全テスト（10 万行の性能テストを含む。計測値は -s で表示）
python -m pytest -m perf -s    # 性能テストだけ
```

画面の撮影は、別の端末で `--server.port 8599` を付けて画面を起動してから行います。

```bash
python scripts/take_screenshots.py --work 作業用フォルダ
```

`docs/images/` に 6 枚の画像を保存し、作業用フォルダにダウンロードした Excel・印刷用ページと、その PDF を保存します。画面に例外が表示された場合は撮影を中止します。

## 7. 集計の SQL を変えるとき

1. `sql/` に新しい番号のファイル（例：`003_abc_threshold.sql`）を作ります。適用済みのファイル（`001`・`002`）は書き換えません。
2. ビューを変える場合は、新しいファイルに `DROP VIEW` と `CREATE VIEW` を書きます。
3. `python -m pytest` で、標準ライブラリの計算との突き合わせ（TC-020〜TC-034）が通ることを確認します。
4. 基本設計書の「指標の定義」とテーブル定義書のビュー一覧を更新します。

## 8. 困ったとき

詳しい対応は [09_障害対応手順書](09_障害対応手順書.md) を参照してください。

| 症状 | 確認すること |
|---|---|
| 「必須の列がありません」と表示される（ERR-004） | 1 行目の列名が入力データ仕様と同じか（前後の空白は無視される） |
| 「文字コードを判定できません」と表示される（ERR-002） | CSV を UTF-8 または Shift_JIS で保存し直す |
| 指標が「—」になる | 前年同月・前月のデータを読み込んでいるか。比べる月（前年同月・前月）の売上、または対象期間の売上が 0 以下でないか |
| Excel の得意先名の先頭に「'」が付いている | 名称が「=」「+」「-」「@」などで始まっている。数式として動かないように付けたもの（ADR-0003） |
| 画面に英語で「This app has encountered an error. The original error message is redacted to prevent data leaks. Full error details have been recorded in the logs (if you're on Streamlit Cloud, click on 'Manage app' in the lower right of your app).」とだけ表示される（ERR-201） | 起動した端末に、エラーの種類と、エラーが起きるまでに通った処理の一覧（トレースバック）が表示されている。画面には例外の種類・ファイルの場所などを出さない設定（`.streamlit/config.toml` の `showErrorDetails = "none"`）にしているため、この文だけが表示される |

## 9. 定期点検

| 時期 | 確認すること | 確認の方法 |
|---|---|---|
| 毎日 | 該当なし（常駐する処理がなく、使うときだけ起動するため） | — |
| 毎月（読み込みのたび） | 除外した行・読めなかったファイルの件数と理由。毎月同じ理由で除外される行がある場合は、販売管理システムの出力の設定を見直す | 画面上部の帯と「取込結果」タブ（09_障害対応手順書.md 3 章） |
| 毎月（読み込みのたび） | 集計したい月がすべて「期間」の選択肢に表示されているか | サイドバーの「期間」 |
| 変更時（SQL・ライブラリ・設定） | 自動テストが全件合格するか | `python -m pytest`（7 章・05_テスト仕様書.md） |
| 変更時（ライブラリ・設定） | 画面に例外が表示されないか、文字の欠け・重なりがないか | 6 章の画面の撮影（`scripts/take_screenshots.py`） |
| 変更時（設定） | 待ち受けが `127.0.0.1` だけか | `ss -ltn`（05_テスト仕様書.md TC-084） |

## 10. バックアップと戻し方

| 対象 | 内容 | 控えの置き場所 | 戻し方 |
|---|---|---|---|
| 読み込んだ明細 | 画面はメモリ上にだけ持ち、ディスクに書かないため、画面側で控えるものはない | — | 元のファイルを読み込み直す |
| 元の売上明細（CSV・Excel） | 集計の元になるファイル。画面は書き換えない | 販売管理システム、または利用者が保存した場所。保管場所と保管期間は運用で決める項目 | 販売管理システムから出力し直す、または保管場所から写す |
| 出力した Excel・印刷用ページ | 会議資料として配布するファイル | 利用者が保存した場所。保管場所と保管期間は運用で決める項目 | 元の明細を読み込み、同じ絞り込み条件で出力し直す |
| プログラム・SQL・設定 | `app/`・`sales_dashboard/`・`sql/`・`.streamlit/config.toml`・`requirements.txt` | Git のリポジトリ（版ごとのタグ） | `git checkout <タグ>` で戻し、`pip install -r requirements.txt` で固定した版のライブラリを入れ直す。戻した後に `python -m pytest` で確認する |

## 11. 資格情報・鍵・トークンの更新

該当なし。画面に認証がなく（利用者の PC の 127.0.0.1 だけで使う前提）、外部のサービスにもデータベースにも接続しないため、パスワード・API キー・トークンを持ちません。データベースはメモリ上の SQLite で、接続の資格情報を使いません。

社内で共有して使うために認証や外部のデータベースを加える場合は、この章に保管場所と更新手順を追記します。

## 12. 連絡体制

| 役割 | 担うこと | 連絡する相手 |
|---|---|---|
| 利用者 | 画面の表示（帯・理由の文言）を確認し、元のファイルを直して読み込み直す。直らない場合は相談する | 運用担当者 |
| 運用担当者 | 09_障害対応手順書.md の 3・4 章で切り分けと対処を行う。販売管理システムの出力の設定を確認する。障害を記録する（同 6 章） | 保守担当者 |
| 保守担当者 | ERR-201・想定外の例外の調査、SQL・プログラム・ライブラリの修正、自動テストでの確認 | — |

各役割の担当者・連絡手段・連絡までの目安の時間は運用で決める項目とし、この文書には書きません。
