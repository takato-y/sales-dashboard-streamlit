## 背景

利用者は経理・営業の担当者で、ファイルを選んで絞り込みを切り替える程度の操作で使えることが求められる（REQ-103）。同時に利用するのは 1 人で、PC の中だけで動けばよい（REQ-102）。

## 検討した案

| 案 | 長所 | 短所 |
|---|---|---|
| A. Excel のピボットと VBA | 利用者が慣れている | 明細の検証結果の一覧や、条件を変えた再集計を作り込む量が多い。10 万行で動作が重くなりやすい |
| B. Streamlit（Python） | pandas の集計をそのまま画面にできる。ファイル選択・絞り込み・ダウンロードの部品が標準である | 画面の細かな配置の自由度は低い。複数人での利用には向かない |
| C. Web フレームワーク（Flask など）＋ JavaScript のグラフ | 画面を自由に作れる | 画面の作り込みが多く、この規模には過剰 |

## 決定

B を採用する。集計の処理は Streamlit に依存しない Python のパッケージ（`sales_dashboard`）に分け、画面（`app/`）からはそれを呼ぶだけにする。これにより、集計の正しさを画面なしで自動テストできる。

## 結果

- 画面は `127.0.0.1` だけで待ち受ける設定にする（`.streamlit/config.toml` と起動コマンドの両方で指定）
- 認証がないため、社内ネットワークへの公開はしない。必要になった場合は別途検討する
